# 퍼짐

공개 콘텐츠를 읽고, 보완할 요소와 다음 콘텐츠의 구성안을 제안하는 도구입니다.

[프로젝트 소개 PDF](docs/퍼짐-프로젝트소개.pdf) | [기획서](docs/PRD.md) | [기능 검증과 통계 기록 Excel](docs/퍼짐-기능검증과통계기록.xlsx)

## 소개

다음 콘텐츠를 기획할 때는 소재 목록뿐 아니라 어떤 자료를 읽었고 왜 그 제안을 하는지 확인할 수 있어야 합니다. 퍼짐은 채널의 공개 글을 기준으로 보완할 요소와 콘텐츠 두 안을 보여주고, 사용자가 구성과 선택 이유를 검토하도록 만들었습니다.

현재 자동 분석 대상은 **공개 피드(RSS)를 제공하는 블로그의 제목과 본문 일부**입니다. RSS는 사이트가 새 글을 제공하는 공개 목록입니다. Instagram 개별 게시물과 이미지, 비공개 반응 통계는 자동으로 읽지 않습니다.

## 사용 흐름과 기능

**주소 입력 → 확인한 자료 읽기 → 콘텐츠 두 안 비교 → 선택적으로 반응 기록**

| 기능 | 확인할 내용 |
|---|---|
| 내 SNS 분석 | 공개 자료를 읽을 수 있었는지와 보완할 요소를 확인합니다. |
| 다음 콘텐츠 추천 | 기준 글, 콘텐츠 두 안과 선택 이유를 함께 보여줍니다. |
| 오늘과 이번 주 키워드 | 소재와 관련 뉴스 근거를 확인합니다. |
| 상세 통계 | 직접 입력한 게시물별 반응을 계산합니다. 자동으로 수집한 비공개 통계가 아닙니다. |

읽지 못한 정보는 ‘확인하지 못함’으로 표시합니다. 주소 등록과 실제 콘텐츠 열람 가능 여부를 구분하며, 계정 이름만 확인했을 때 게시물 내용이나 반응을 추정하지 않습니다.

## 토스 머니북 사례

메인 화면의 ‘토스 머니북 분석 사례 보기’에서는 공식 공개 자료, 채널의 역할, 후속 콘텐츠 두 안과 선택 이유를 볼 수 있습니다. 출간 발표, 공식 에디션과 제작 회고를 구분해 읽고 제안의 근거로 연결했습니다.

다른 토스 공개 자료에서 참고한 판단도 원문 내용, 적용 예시와 적용 한계로 나눴습니다. 첫 장면의 메시지, 실제 경험과 소재의 연결, 다음 편을 찾을 이유 등을 검토하는 기준으로 사용합니다.

이 사례는 공개 자료를 읽고 만든 독립 분석입니다. 실제 캠페인을 집행한 경험이나 SNS 성과를 보장하는 방법으로 제시하지 않습니다. 상세 근거는 [사례와 추천 기준](docs/CASE-STUDY.md), [사례 원자료](docs/toss-case.json)에 있습니다.

## 검증 결과와 한계

자동 검사 27개로 주소 처리, 공개 자료 해석, 자료 미확인 표시, 추천 범위와 통계 계산을 확인했습니다. 실제 Instagram 주소에서 이름만 확인되는 경우에도 읽지 못한 소개와 게시물 반응을 추정하지 않는 처리를 확인했습니다.

추천은 공개 글의 표현에 적용한 규칙입니다. 검색량은 SNS 조회수와 다르며, 반응률이나 전체 반응 수만으로 원인을 확정하지 않습니다. 실제 바이럴 증가와 이용자 효과는 아직 측정하지 않았습니다.

## 실행하기

Node.js 22 이상에서 저장소 최상위 폴더의 터미널에 입력합니다. 별도 패키지 설치와 인증값 입력은 필요하지 않습니다.

```sh
npm start
```

브라우저에서 http://127.0.0.1:4191/ 을 엽니다. 자동 검사는 다음 명령으로 실행합니다.

```sh
npm test
```

| [소개 PDF](docs/퍼짐-프로젝트소개.pdf) | 문제와 화면, 프로젝트 판단 |
| [검증 Excel](docs/퍼짐-기능검증과통계기록.xlsx) | 기능 확인과 통계 계산 기록 |

상세 통계와 선택 기록은 브라우저에, 키워드 수집 기록은 로컬 `runtime/`에 보관합니다. 개인 입력 기록은 GitHub에 포함하지 않습니다.

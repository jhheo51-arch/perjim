# Trend to Trust 통합 기획서

작성일: 2026년 10월 8일
목적: 토스 Brand Marketing Specialist 지원용 개인 포트폴리오

## 1. 프로젝트 정의

Trend to Trust는 **돈을 쉽게 이해하도록 돕는 토스라는 인식을 목표로, 가계부를 생활 소재로 사용한 브랜드 캠페인**이다. 캠페인의 목표와 제품 기능 개발을 구분하며, 콘텐츠 제작과 제휴 제안을 보여준다. 실제 독자 반응은 아직 확보하지 않았다.

내부 도구 ‘퍼짐’은 공개 콘텐츠와 검색 관심 자료의 확인 범위를 기록하고 다음 콘텐츠 두 안을 비교한다. ‘한 달의 이유’는 대표 캠페인이고 퍼짐은 후반부의 보조 도구다. 카드 6장과 첫·후속 뉴스레터 원고는 제작 완료했으며 영상·제휴·독자 검증은 별도 상태로 표시한다.

## 2. 해결하려는 문제

브랜드 마케팅 포트폴리오는 완성된 광고 이미지만으로 지원자의 판단 과정을 보여주기 어렵다. 반대로 분석 도구만 제시하면 브랜드 메시지와 콘텐츠 감각이 약하게 보일 수 있다.

따라서 이 프로젝트는 다음 네 질문에 답한다.

1. 어떤 공개 신호를 확인했는가?
2. 그 신호를 왜 토스의 브랜드 과제로 해석했는가?
3. 같은 메시지를 매체와 외부 파트너에 맞게 어떻게 바꿨는가?
4. 반응을 보고 무엇을 수정하며, 아직 무엇을 모르는가?

## 3. 주요 독자와 읽는 상황

제작 기준과 현재 상태는 [브랜드 캠페인 제작 기준](CAMPAIGN-BRIEF-2026-10-08-v01.md), 실제 원고는 [콘텐츠 페이지](../campaign.html)를 따른다.

### 주요 독자

- 토스 브랜드 마케팅 채용 담당자와 실무자
- 지원자의 역할, 판단 근거, 실행 범위와 과장 여부를 확인하려는 면접관

### 읽는 상황

- 첫 60초: 프로젝트 한 문장, 지원자의 역할, 실제·가상 범위를 파악한다.
- 다음 3분: 브랜드 목표→콘텐츠→근거→제휴→검증 계획 흐름을 훑는다.
- 심층 확인: 퍼짐 도구, 원문 출처, 기획서와 자동 검사 기록을 확인한다.

## 4. 핵심 이야기

> ‘토스는 내 돈을 쉽게 이해하도록 돕는다’는 인식을 목표로, 가계부를 소재로 한 브랜드 캠페인 ‘한 달의 이유’를 기획하고 콘텐츠를 제작했습니다.

이 문장을 모든 산출물의 기준으로 사용한다. 퍼짐을 별도 서비스로 과도하게 설명하지 않고, 캠페인 판단의 추적 가능성을 높인 업무 도구로 배치한다.

## 5. 전체 업무 흐름

| 단계 | 입력 | 판단 | 출력 |
|---|---|---|---|
| 1. Collect | 공개 피드, 검색 관심, 공식 통계·플랫폼 자료 | 읽은 범위와 미확인 범위를 구분 | 근거 링크와 신호 목록 |
| 2. Interpret | 생활비·정보 탐색·콘텐츠 깊이 신호 | 사실과 캠페인 가설을 구분 | ‘내 돈의 흐름 이해’라는 기회 |
| 3. Translate | 토스의 쉬운 언어와 신뢰 역할 | 금액보다 생활 이유를 이해하도록 설계 | 가계부 연재물 ‘한 달의 이유’ |
| 4. Craft | Meta, YouTube·Google, 온드 채널 문법 | 발견→이해→행동을 매체에 맞게 조정 | 채널별 가계부 소재와 확인 지표 |
| 5. Partner | 어피티·오늘의집·캐릿 공개 자료 | 경제·생활·트렌드 역할로 구분 | 역할별 공동 콘텐츠 제안 |
| 6. Learn | 익명 참여자 5명의 메시지 A/B 선택 | 숫자 명확성·세부 근거 요청 확인 | 숫자→근거→행동 2차안 |
| 7. Validate | 2차 문장과 채널 제작물 | 메시지 이해와 다음 행동 재확인 | 다음 사용자 검증 기록 |

## 6. 화면 정보 구조

1. 대표 메시지와 가상 이야기: 신규 가계부 기능처럼 오해되지 않게 표시.
2. 브랜드 목표: 형성하고 싶은 인식, 캠페인의 역할, 확인할 변화.
3. 완성 콘텐츠: 카드 6장·뉴스레터 원고와 내려받기.
4. 공개 신호와 해석: 가설의 출발점이며 고객 욕구 검증과 구분.
5. 채널별 역할: 카드·원고 제작 완료, 영상은 구성 제안.
6. 파트너 제안: 어피티 협업의 추가 가치와 실행 조건.
7. 가상 의견 예시: 실제 학습 결과가 아닌 분류 방식의 시연.
8. 퍼짐: 보조 도구 설명과 기술 검증을 펼쳐 확인.
9. 역할·범위·실제 독자 검증 계획.

## 7. 퍼짐 기능 범위

| 기능 | 동작 | 결과의 한계 |
|---|---|---|
| 공개 콘텐츠 분석 | 허용된 SNS 주소와 공개 RSS를 읽는다 | 로그인·플랫폼 제한으로 일부 정보를 읽지 못할 수 있다 |
| 확인 상태 표시 | 읽은 항목과 ‘확인하지 못함’을 보여준다 | 빈값을 0 또는 추정치로 바꾸지 않는다 |
| 관심 신호 확인 | Google Trends 공개 피드와 사용자가 확인한 자료를 기록한다 | 검색 관심과 SNS 반응을 같은 지표로 보지 않는다 |
| 콘텐츠 두 안 | 읽은 자료와 입력 주제로 후속안을 비교한다 | 성과를 예측하거나 우수안을 자동 확정하지 않는다 |
| 반응 기록 | 동일 조건의 최근 자료를 비교한다 | 인과관계와 통계적 유의성을 주장하지 않는다 |
| 판단 기록 | 선택 이유와 다음 검증을 브라우저에 저장한다 | 개인 기록은 제출 저장소에 포함하지 않는다 |

추천은 정해진 규칙을 적용하며 외부 생성형 AI 모델을 호출하지 않는다. 공개 글이 없거나 소재 연결이 약하면 대안의 우위를 만들지 않는다.

### 키워드 근거 연결

퍼짐은 키워드 하나를 다음 자료로 나눠 확인한다.

| 역할 | 자료 | 화면에서 보여주는 내용 |
|---|---|---|
| 새 소재 발견 | Google Trends 급상승 RSS | 오늘 갑자기 검색되는 주제 |
| 국내 관심 검증 | NAVER API Hub 검색어 트렌드 | 최근 7일과 이전 7일의 상대 검색 관심 |
| 영상과 문화 반응 | YouTube Data API | 최근 관련 영상의 현재 누적 조회와 댓글 |
| 사건 배경 확인 | Google 뉴스 RSS와 빅카인즈 원문 | 관심이 생긴 배경과 기사 맥락 |
| 신조어와 생활 맥락 | 트렌드어워드와 썸트렌드 공개 자료 | 표현의 뜻과 사용 상황 |

자동 연결 자료와 원문에서 직접 확인할 자료를 구분한다. 인증값이 없거나 응답이 실패하면 0으로 표시하지 않고 연결 전 또는 확인 실패로 표시한다. NAVER API Hub는 최근 14일의 일간 상대지수를 최근 7일과 이전 7일로 나눠 평균을 비교한다. 검색 관심, 영상 조회, 댓글과 뉴스 기사는 서로 다른 단위이므로 합산하지 않는다.

2026년 10월 8일 로컬 환경에서 시험 키워드 `가을`로 NAVER API Hub 실제 호출을 확인했다. 최근 7일 평균 74.8, 이전 7일 평균 61.5, 변화율 21.6%가 계산됐다. 이는 검색 횟수가 아닌 조회 범위 안의 상대지수다. 공개 배포 환경의 인증값 설정은 아직 확인하지 않았다.

## 8. 채널과 제휴 설계 기준

### Meta

- 역할: 생활 장면으로 관심을 멈춰 세운다.
- 소재: 1080×1350 카드뉴스 6장과 게시글 문안 제작 완료. 실제 게시 전 검수 필요.
- 확인: 메시지 이해·브랜드와 이유 회상. 저장·이동은 보조 행동 지표.

### YouTube·Google

- 역할: 관심을 이해와 신뢰로 바꾼다.
- 소재: 3분 설명 영상과 15초 유입 영상 구성 제안. 영상 제작·집행은 미수행.
- 확인: 실제 광고 배치·기간·분모를 확정한 뒤 브랜드 회상과 시청 행동을 분리해 검토.

### 토스 온드 채널

- 역할: 브랜드 약속을 제품 경험으로 증명한다.
- 소재: 웹에서 읽는 전체 콘텐츠와 첫·후속 원고. 실제 토스 채널 게재·제품 기능 연결은 미수행.
- 확인: 이해한 메시지, 기억나는 브랜드와 이유, 후속 회고. 앱 가입·알림 기능을 전제하지 않음.

### 외부 파트너

- 1순위 어피티: 경제 해석. 머니레터와 영상으로 소비 회고를 설명한다.
- 2순위 오늘의집: 생활 맥락. 1–2인 가구의 집과 지출 이유를 연결한다.
- 3순위 캐릿: 트렌드 검증. 20대 소비 이유를 투표·서베이·인터뷰 형식으로 확인한다.
- 상세 제안: [어피티 협업 방안](UPPITY-PROPOSAL-2026-10-08-v01.md).
- 실제 제휴 전 확인: 광고 표기, 금융 표현 검수, 제작비, 사용 권리, 일정과 지표 공유 범위.
- 상세 근거: `docs/PARTNER-SHORTLIST-2026-10-08-v01.md`.

## 9. VOC와 검증 설계

초기 화면의 VOC 12건은 인터랙션을 보여주기 위한 가상 자료였으며, 현재 대표 포트폴리오에서는 실제 메시지 검증 기록으로 교체했다.

2026년 10월 8일 최소 검증으로 익명 참여자 5명에게 숫자 중심 A안과 이유 중심 B안을 같은 조건으로 보여줬다. A안은 4명에게 선택됐고, 5명 모두 세부 구성·원인을 더 알고 싶다고 답했다. 이 관찰을 전체 고객의 비율이나 성과로 확대하지 않는다.

다음 검증은 숫자+이유 2차안과 기존 A안을 같은 조건으로 보여주고 다음을 기록한다.

2차 참여 화면은 [message-check-02.html](../message-check-02.html)이다. 가상 내역에서 증가 원인을 단정하지 않도록 B안을 `18% 늘어난 배달비, 야근한 화요일 4번을 함께 돌아봐요.`로 수정했다. 응답은 아직 수집 전이며 1차 응답과 다른 브라우저 저장 공간에 기록한다.

- 한 문장으로 이해한 메시지
- 근거가 충분하다고 느낀 지점
- 누르고 싶은 다음 행동
- 기억나는 브랜드와 그 이유
- 실제 고객 사례·거래 분석 기능으로 오해한 부분
- 1차안과 2차안 중 선택 및 선택 이유

응답 원문, 관찰 사실, 지원자의 해석을 나누며 표본 비율을 전체 고객의 결과로 확대하지 않는다.

## 10. 성공 기준

### 포트폴리오 성공 기준

- 첫 화면에서 도구와 캠페인의 관계를 15초 안에 이해할 수 있다.
- 모든 수치와 VOC가 실제 자료인지 시뮬레이션인지 구분된다.
- 채용 공고의 세 업무인 외부 제휴, 매체별 소재, 결과 반영을 각각 찾을 수 있다.
- GitHub에서 실행 방법과 검증 결과를 확인할 수 있다.

### 실제 캠페인 검증 시 볼 지표

- 발견: 3초 시청률과 소재별 도달
- 이해: 핵심 메시지 회상과 근거 구간 시청
- 행동: 자기 회고 안내 도달과 후속 참여
- 브랜드: 돈을 쉽게 이해하도록 돕는다는 연상과 그 이유
- 관계: 재방문과 후속 콘텐츠 반응. 클릭·재방문을 신뢰와 동일시하지 않음

지표 변화만으로 원인을 확정하지 않고 소재, 매체, 유료 노출, 관측 기간을 함께 기록한다.

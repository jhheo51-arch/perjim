# Trend to Trust 통합 기획서

작성일: 2026년 10월 8일
목적: 토스 Brand Marketing Specialist 지원용 개인 포트폴리오

## 1. 프로젝트 정의

Trend to Trust는 **트렌드 신호를 수집하고, 브랜드의 언어로 번역하고, 채널별 콘텐츠로 만든 뒤, 반응으로 수정하는 과정**을 보여주는 포트폴리오다.

내부 도구 ‘퍼짐’은 공개 콘텐츠와 검색 관심 자료의 확인 범위를 기록하고 다음 콘텐츠 두 안을 비교한다. 가계부 콘텐츠 시리즈 ‘한 달의 이유’는 그 업무 방식을 토스 브랜드 커뮤니케이션에 적용한 결과다.

## 2. 해결하려는 문제

브랜드 마케팅 포트폴리오는 완성된 광고 이미지만으로 지원자의 판단 과정을 보여주기 어렵다. 반대로 분석 도구만 제시하면 브랜드 메시지와 콘텐츠 감각이 약하게 보일 수 있다.

따라서 이 프로젝트는 다음 네 질문에 답한다.

1. 어떤 공개 신호를 확인했는가?
2. 그 신호를 왜 토스의 브랜드 과제로 해석했는가?
3. 같은 메시지를 매체와 외부 파트너에 맞게 어떻게 바꿨는가?
4. 반응을 보고 무엇을 수정하며, 아직 무엇을 모르는가?

## 3. 주요 독자와 읽는 상황

### 주요 독자

- 토스 브랜드 마케팅 채용 담당자와 실무자
- 지원자의 역할, 판단 근거, 실행 범위와 과장 여부를 확인하려는 면접관

### 읽는 상황

- 첫 60초: 프로젝트 한 문장, 지원자의 역할, 실제·가상 범위를 파악한다.
- 다음 3분: 퍼짐→트렌드→브랜드→채널→VOC 흐름을 훑는다.
- 심층 확인: 퍼짐 도구, 원문 출처, 기획서와 자동 검사 기록을 확인한다.

## 4. 핵심 이야기

> 트렌드와 공개 자료를 수집하고 반응을 기록하는 ‘퍼짐’을 만들고, 여기서 발견한 신호를 토스 가계부 콘텐츠 ‘한 달의 이유’로 발전시켰습니다.

이 문장을 모든 산출물의 기준으로 사용한다. 퍼짐을 별도 서비스로 과도하게 설명하지 않고, 캠페인 판단의 추적 가능성을 높인 업무 도구로 배치한다.

## 5. 전체 업무 흐름

| 단계 | 입력 | 판단 | 출력 |
|---|---|---|---|
| 1. Collect | 공개 피드, 검색 관심, 공식 통계·플랫폼 자료 | 읽은 범위와 미확인 범위를 구분 | 근거 링크와 신호 목록 |
| 2. Interpret | 생활비·정보 탐색·콘텐츠 깊이 신호 | 사실과 캠페인 가설을 구분 | ‘내 돈의 흐름 이해’라는 기회 |
| 3. Translate | 토스의 쉬운 언어와 신뢰 역할 | 금액보다 생활 이유를 이해하도록 설계 | 가계부 연재물 ‘한 달의 이유’ |
| 4. Craft | Meta, YouTube·Google, 온드 채널 문법 | 발견→이해→행동을 매체에 맞게 조정 | 채널별 가계부 소재와 확인 지표 |
| 5. Partner | 어피티·오늘의집·캐릿 공개 자료 | 경제·생활·트렌드 역할로 구분 | 역할별 공동 콘텐츠 제안 |
| 6. Learn | 가상 VOC 12건 | 공감·근거·행동 요구로 분류 | 1차→2차 콘텐츠 수정 |
| 7. Validate | 실제 소규모 사용자 검증 예정 | 메시지 이해와 다음 행동 확인 | 제출 전 실제 관찰 기록 |

## 6. 화면 정보 구조

1. **Hero**: 프로젝트 한 문장, 캠페인과 역할
2. **Project thesis**: VOC를 다음 콘텐츠의 출발점으로 정의
3. **My operating tool**: 퍼짐의 수집→구분→선택→학습 흐름
4. **Trend signal**: 공개 사실과 지원자의 해석 분리
5. **Brand translation**: 사실→가능한 해석→브랜드 역할
6. **Channel craft**: Meta, YouTube·Google, 토스 온드 채널 소재
7. **Partner shortlist**: 실제 채널 3곳의 공개 근거와 제휴 초안
8. **VOC learning loop**: 반응 분류와 콘텐츠 수정
9. **Learn fast**: 짧은 기간의 학습·수정 기록
10. **My role**: 직접 수행, 시뮬레이션, 미수행 범위

## 7. 퍼짐 기능 범위

| 기능 | 동작 | 결과의 한계 |
|---|---|---|
| 공개 콘텐츠 분석 | 허용된 SNS 주소와 공개 RSS를 읽는다 | 로그인·플랫폼 제한으로 일부 정보를 읽지 못할 수 있다 |
| 확인 상태 표시 | 읽은 항목과 ‘확인하지 못함’을 보여준다 | 빈값을 0 또는 추정치로 바꾸지 않는다 |
| 관심 신호 확인 | Google Trends 공개 피드와 사용자가 확인한 자료를 기록한다 | 검색 관심과 SNS 반응을 같은 지표로 보지 않는다 |
| 콘텐츠 두 안 | 읽은 자료와 입력 주제로 후속안을 비교한다 | 성과를 예측하거나 우수안을 자동 확정하지 않는다 |
| 반응 기록 | 동일 조건의 최근 자료를 비교한다 | 인과관계와 통계적 유의성을 주장하지 않는다 |
| 판단 기록 | 선택 이유와 다음 검증을 브라우저에 저장한다 | 개인 기록은 제출 저장소에 포함하지 않는다 |

추천은 정해진 규칙을 적용하며 외부 생성형 AI 모델을 호출하지 않는다. 공개 글이 없거나 소재 연결이 약하면 대안의 우위를 만들지 않는다.

## 8. 채널과 제휴 설계 기준

### Meta

- 역할: 생활 장면으로 관심을 멈춰 세운다.
- 소재: 6초 세로 영상과 4장 캐러셀.
- 확인: 3초 시청률, 저장률, 상세 콘텐츠 이동.

### YouTube·Google

- 역할: 관심을 이해와 신뢰로 바꾼다.
- 소재: 3분 설명 영상과 15초 유입 영상.
- 확인: 15초 유지율, 근거 구간 시청, 온드 채널 이동.

### 토스 온드 채널

- 역할: 브랜드 약속을 제품 경험으로 증명한다.
- 소재: 토스피드 아티클과 앱 내 소비 리포트.
- 확인: 근거 보기, 소비 리포트 진입, 재방문.

### 외부 파트너

- 1순위 어피티: 경제 해석. 머니레터와 영상으로 소비 회고를 설명한다.
- 2순위 오늘의집: 생활 맥락. 1–2인 가구의 집과 지출 이유를 연결한다.
- 3순위 캐릿: 트렌드 검증. 20대 소비 이유를 투표·서베이·인터뷰 형식으로 확인한다.
- 실제 제휴 전 확인: 광고 표기, 금융 표현 검수, 제작비, 사용 권리, 일정과 지표 공유 범위.
- 상세 근거: `docs/PARTNER-SHORTLIST-2026-10-08-v01.md`.

## 9. VOC와 검증 설계

현재 화면의 VOC 12건은 인터랙션을 보여주기 위한 가상 자료다. 실제 사용자 반응으로 표현하지 않는다.

제출 전 최소 검증은 목표 이용자 5명에게 1차·2차 소재를 같은 조건으로 보여주고 다음을 기록하는 것이다.

- 한 문장으로 이해한 메시지
- 근거가 충분하다고 느낀 지점
- 누르고 싶은 다음 행동
- 토스다운 인상과 그 이유
- 1차안과 2차안 중 선택 및 선택 이유

응답 원문, 관찰 사실, 지원자의 해석을 나누며 표본 비율을 전체 고객의 결과로 확대하지 않는다.

## 10. 성공 기준

### 포트폴리오 성공 기준

- 첫 화면에서 도구와 캠페인의 관계를 15초 안에 이해할 수 있다.
- 모든 수치와 VOC가 실제 자료인지 시뮬레이션인지 구분된다.
- 채용 공고의 세 업무인 외부 제휴, 매체별 소재, 결과 반영을 각각 찾을 수 있다.
- GitHub에서 실행 방법과 검증 결과를 확인할 수 있다.

### 실제 캠페인 검증 시 볼 지표

- 발견: 3초 시청률과 소재별 도달
- 이해: 핵심 메시지 회상과 근거 구간 시청
- 행동: 소비 리포트 진입과 근거 보기
- 관계: 재방문과 후속 콘텐츠 반응

지표 변화만으로 원인을 확정하지 않고 소재, 매체, 유료 노출, 관측 기간을 함께 기록한다.
